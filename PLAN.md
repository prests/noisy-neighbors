# Noisy Neighbor — Entity Sound Controls & Zones

## Context
- The repo is a clean Fabric Minecraft Java **26.3 / Java 25** starter. It has one initializer and no feature code. This plan adds personal **client-only** volume controls for **vanilla living mobs and animals**; no blocks, players, nonliving entities, modded mobs, or server installation in v1.
- The wireframes show a button in Music & Sound Options, searchable global mob sliders, a world list, a zone list, and searchable zone sliders. Players define each named 3D box by **right-clicking two blocks with a feather**. A toggle shows zone outlines in the world.

## Approach
- Ship a **static 26.3 catalog** (`mob_sounds.json`) mapping vanilla mob registry IDs to explicit vanilla sound-event IDs, including baby/sound variants; maintain a separate set of shared vanilla mob sound-event IDs. Build immutable reverse maps at startup for fast lookup; validate missing/duplicate/ambiguous IDs and catalog coverage against 26.3 registries. Display friendly names using Minecraft entity translations, with registry IDs available in UI/tooltips. **No prefix-based runtime guesswork**; unknown event IDs, blocks, players and modded sounds pass through.
- In the client audio path, for **mob-specific cataloged event IDs**, map to the mob even if the sound is positional (so `/playsound` of a known mob event follows the mod rules). If a source entity is available but is a mismatched, non-vanilla, or player entity, **do not alter its sound: play it at its original Minecraft volume**. For **shared** IDs such as `generic_swim`, apply a mob slider **only** when the sound identifies a vanilla mob entity; positional shared events likewise play unmodified. Do not infer an emitter by proximity. Minecraft 26.3 sends `/playsound` and natural positional sounds with the same packet fields; distinguishing them is impossible client-only and *intentionally unnecessary*: known events follow the rules at their supplied position.
- Final volume = original vanilla volume (including master/category) × global multiplier (0–1) × each enabled matching zone multiplier (0–1). Missing override means 1.0; 0 mutes; no amplification. Evaluate the **sound source's position at start**, not the player's. Capture the multiplier once per sound instance (including moving/continuous sounds); no zone-boundary changes during playback. Keep vanilla master/category volume controls functional independently. Verify both initial and subsequent tick/category-recalculation paths in `SoundEngine`, including zero-volume starts.
- Zones use `min/max` block coordinates on all axes, with containment `min <= floor(sound coordinate) <= max` (equivalent to block volume `[min, max+1)`). Clicking two blocks at the same Y selects exactly that single-block-high layer. Normalize reversed corners and negative coordinates. Selection mode starts from **Create Zone/Edit Bounds**, intercepts main-hand feather right-clicks on blocks on the client only, shows first-corner feedback and a preview outline, commits on second corner, and exits/cancels cleanly. No new game item, server packet, or tool customization. Saved zones are named, enabled/disabled, editable (name/bounds/volumes), and removable; show outlines for current dimension only when toggled.
- One local JSON file under the Minecraft config directory stores sparse global overrides, known worlds (display name), and zones (stable local zone ID, dimension registry ID, bounds, per-mob overrides), with schema version and validated 0–100 inputs. Load on client startup; save on edits with atomic replacement/fallback, retain old file and surface errors on corrupt/unwritable data. Key single-player worlds by **save directory ID**, multiplayer by normalized **server endpoint**, and zones by dimension ID. Never use editable display name as identity; reset active zone/selection state on leave/switch. The vanilla client cannot uniquely identify separate proxy-hosted worlds sharing endpoint + dimension; **document this accepted collision risk** (Litematica-style), no manual profiles or server protocol.
- Build UI with vanilla `Screen`, searchable/scrollable list widgets, `EditBox`, buttons and sliders, localized labels and narration. Small mixin adds **Advanced Sound Controls** to `SoundOptionsScreen`; world/zone lists and editing follow the supplied wireframes. World list includes saved worlds and highlights the current one; zone list labels/filter dimensions; unavailable worlds can be renamed/browsed but selecting corners requires being in that actual world. Clear empty states and navigation, keyboard focus, back/cancel, and a zone-outline toggle. Fabric API already supplies client events and 26.3 world-render callbacks; **no MaLiLib, ModMenu, other mandatory mods, or additional UI/config libraries**.

## Architecture / files to modify
- `src/main/resources/fabric.mod.json`, `src/main/resources/noisy-neighbors.client.mixins.json`: client entrypoint and narrowly scoped mixins; mark client-only environment so dedicated servers do not load it.
- `src/main/java/com/github/prests/noisyneighbors/NoisyNeighbors.java`: retain `MOD_ID` and minimal initializer; `client/NoisyNeighborsClient.java` wires client lifecycle, selection, persistence, rendering.
- `client/sound/MobSoundCatalog.java` + `src/main/resources/assets/noisy-neighbors/mob_sounds.json`: catalog validation, friendly mob/event lookup, shared IDs and reverse maps. Catalog data is curated against vanilla 26.3 events/animal variant JSONs (not dynamic registry guessing).
- `client/sound/VolumePolicy.java`, `client/sound/SoundEngineMixin.java`, `client/sound/EntityBoundSoundAccessor.java`: determine mob and start position; snapshot multiplier once; apply it only to cataloged sounds during initial and continuing playback while preserving Minecraft's category/master volume. Keep mixin implementation scoped to exact 26.3 signatures, confirm accessors/zero-volume behavior with a prototype before fleshing out UI.
- `client/zone/Zone.java` (incl. normalized bounds/containment), `client/zone/ZoneSelection.java`, `client/zone/ZoneOutlines.java`: immutable-ish zone geometry/rules, feather selection state machine, optional 26.3 Fabric world outlines (use built-in render pipelines; avoid custom GPU resources if unnecessary).
- `client/config/WorldIdentity.java`, `client/config/SettingsStore.java`: safe world/dimension keys, JSON versioning and persistence; load only local client data. `client/ui/GlobalSoundScreen.java`, `WorldListScreen.java`, `ZoneListScreen.java`, `ZoneEditScreen.java`, `MobVolumeList.java`: UI screens and shared search/slider component; `client/ui/SoundOptionsScreenMixin.java` adds the entry button.
- `src/main/resources/assets/noisy-neighbors/lang/en_us.json`: localized labels and descriptions. `README.md`: controls, scope, install, attribution caveats and proxy collision caveat. `build.gradle`: only minimal test-scope setup if needed; no runtime dependency changes expected.

## Reuse / research evidence
- Existing `NoisyNeighbors.MOD_ID` and Fabric API dependency in `build.gradle`.
- Checked local 26.3 mapped Minecraft JAR: `ClientboundSoundEntityPacket` identifies an entity; `EntityBoundSoundInstance` retains it; `ClientboundSoundPacket` and `/playsound` carry event, category, XYZ, volume, pitch, seed **but no emitter or command flag**. Cow (`AbstractCow`) and Pig override the `LivingEntity` generic hurt fallback with distinct hurt variants; `Entity.getSwimSound()` defaults to `GENERIC_SWIM`, shared by some mobs. 26.3 has `SoundEngine.play`, `calculateVolume(SoundInstance)`, `SoundOptionsScreen`, `AbstractSliderButton`, and `ObjectSelectionList`.
- [Sound Controller](https://github.com/BVengo/sound-controller) demonstrates vanilla widgets + sound-engine mixins + per-server regions without MaLiLib; it controls sound events rather than reliable mob identity. Follow its research lead, **not its source/assets**. [Litematica `DataManager`](https://github.com/maruohon/litematica/blob/271833c7/src/main/java/litematica/data/DataManager.java) persists per world/server and dimension; it needs MaLiLib and cannot solve vanilla proxy-world identity. [Fabric world-render documentation](https://docs.fabricmc.net/develop/rendering/world) covers 26.x extraction/drawing; verify 26.3 event names/API at implementation time. [WorldEdit selection docs](https://worldedit.enginehub.org/en/latest/usage/regions/selections/) informed the feather-tool choice.
